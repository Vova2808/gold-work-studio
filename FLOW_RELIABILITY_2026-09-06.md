# Flow: результат работ 6 сентября 2026

## Итог

Продлённый SOCKS5-прокси сохранён для двух существующих аккаунтов через Windows safeStorage. Секреты не записаны в исходники или этот документ. Оба аккаунта выходят через IP прокси, используют отдельные Electron Session/CONNECT-мосты и не делят cookies/storage.

Пул Flow поддерживает до пяти аккаунтов: новые записи получают собственный случайный id, persistent partition, cookies/storage, token/runtime, локальный SOCKS-мост, очередь и project cache. Для нового аккаунта прокси нужно задать до входа, после чего отдельно пройти Google-вход и проверку Flow; доступ и лимиты самого Google всё равно должны быть действующими. Это локальная изоляция, а не обещание неотслеживаемости со стороны Google: общий IP, устройство и история аккаунтов могут позволять внешнему сервису сопоставить сессии.

**Flow восстановлен и подтверждён реальной генерацией:** оба аккаунта создали и скачали по одному PNG. Для каждого изображения повторное скачивание сохранённого remote job совпало по SHA-256 и не вызвало новый generation POST. Причина и итоговые доказательства приведены в разделе «Flow восстановлен: подтверждённый итог»; промежуточные региональные отказы ниже оставлены как хронология диагностики. Музыку/SFX не меняли.

## Исправления

- SOCKS5: потоковый разбор фрагментированных/объединённых ответов, авторизация, deadline/отмена, закрытие сокетов, маскирование credentials. Невалидный proxy не превращается в прямое подключение.
- При смене прокси сначала блокируются старый маршрут и соединения. Runtime пересоздаётся; конфигурация кешируется и сериализуется.
- Cookies/storage аккаунтов разделены; повторный импорт удаляет старые session chunks, чужие домены не импортируются. Разрешения геолокации и устройств запрещены. Существующая политика WebRTC запрещает непроксируемый UDP.
- API и скачивание изображений/redirect используют исходную Electron Session, без Node direct fallback. Авторизация не передаётся на CDN.
- Запросы одного аккаунта последовательны; другие аккаунты независимы. Добавлены таймауты, AbortSignal и корректное ожидание загрузки runtime.
- 401: один refresh, затем `needs_login`; никакого оживления отклонённой сессии очередью.
- Поддержаны ответы `image.generatedImage.mediaId/fifeUrl/encodedImage` и актуальная форма ID проекта из изученного расширения.
- Принятый image job сохраняется в очереди; retry продолжает скачивание с того же аккаунта без нового POST. Неопределённый ответ, отмена после POST и ошибка локального сохранения без remote ID блокируют слепую повторную оплату. Исходные референсы для resume уже не нужны.
- Новый явный вариант изображения **Google Flow — только Flow**. Не чередует провайдеров и не включает AnyModel fallback; портрет героя также учитывает этот выбор. Старые варианты проектов сохранены для совместимости.
- Ненастроенный реальный провайдер/пустой промпт больше не подставляет Mock-заглушку. Flow-референсы должны быть локальными файлами/data URI: удалённые URL не скачиваются в обход аккаунтного прокси, потерянные референсы не игнорируются.
- Региональный отказ получает `needs_user_action`/`no-retry`; фоновое обновление токена не скрывает его. После успешной ручной проверки Flow блокировка снимается. Исправлен возврат с нового домена Flow после входа.

Основной код: `apps/desktop/src/flow-*.ts`, `proxy-utils.ts`, `mock-generation-pipeline.ts`; контракт/переключатель — `packages/shared/src/index.ts`, `apps/renderer/src/App.tsx`.

## Что проверялось до найденной причины

Прокси отвечает; IPinfo определяет адрес как US. Это не доказывает, как страну определяет Google. Очистка HTTP-кеша не сняла отказ; cookies не очищались. В обычном runtime видны русский язык и Europe/Moscow. Причинная связь с отказом не доказана. Диагностический запуск с изменёнными locale/timezone не дал завершённого сравнения; в production подмена не добавлена.

Полную неотслеживаемость не обещаем: общий IP, характеристики устройства и история аккаунтов могут связывать сессии. Требуется сравнение **этих же аккаунтов и этого же прокси** с работающей сессией Dolphin. Не копировать из расширения plaintext-хранилище cookies, общий partition или слепые повторы.

### Уточнение после проверки миграции Flow

- Пользователь подтвердил: в рабочем Dolphin стартовая страница — `labs.google`, проект — `flow.google.com`. На этом промежуточном этапе трассировка Gold подтверждала переход на новый домен без popup; позже именно этот переход скрытого runtime был локализован как причина отказа.
- `captures/flow-migration-identity-20260906/report.json`: у обоих аккаунтов новый сайт видит **тот же email**, что старая сессия (в отчёте только boolean, без адресов). Перепутанные аккаунты и отсутствие Google cookies в этой проверке не подтвердились. Прокси и cookie isolation повторно проверены для обоих аккаунтов.
- На старом сайте `general.fetchToolAvailability`: первый аккаунт `AVAILABLE`, второй `UNAVAILABLE`; оба после перехода получают `flow.google.com/unsupported-country`. Один лишь старый API/баланс не доказывает готовность нового интерфейса.
- `captures/flow-migration-settled-20260906/report.json`: первый аккаунт с диагностическими `en-US` и `America/New_York` всё равно получает региональный отказ. Эти два параметра сами по себе проблему не решают; в production их подмена не добавлена.
- SOCKS5 предварительная проверка теперь ждёт до 30 секунд вместо 15: наблюдались медленные подключения. Это исправляет слишком короткое ожидание, **не** региональный отказ.
- QA-проба теперь дожидается документа после миграции, а не принимает промежуточную пустую страницу за окончательный результат. Сохраняет только разрешённые региональные/config-флаги и результаты сравнения личности, не ответы auth API.
- Повторно прошли 42 целевых теста Flow/proxy и desktop typecheck. Новых запросов генерации не отправляли, кредиты для генерации не расходовали. Причина различия с рабочим Dolphin пока не доказана; необходима проверка, что там работают оба этих аккаунта с тем же прокси.

Пользователь подтвердил, что в Dolphin работает тот же Google-аккаунт. Это пока не является отдельной проверкой двух аккаунтов в Dolphin.

- `captures/flow-transient-profiles-20260906/report.json`: проверен первый аккаунт в двух **временных memory-only** сессиях. В обеих Google распознал исходный аккаунт и показал `unsupported-country`. Оригинальные cookies не очищались; временные сессии удалены после проверки.
- `captures/flow-chromium142-20260906/report.json`: отдельный Electron **39.8.2 / Chromium 142.0.7444.265** также получил отказ при правильной авторизации и том же выходном IP. Основной Electron 36 не обновлялся, его cookie-база не мигрировала. Официальный архив runtime остаётся в стандартном Electron download cache.
- Добавлены повторяемые QA-инструменты: `--profile-window --native-profile --transient-profiles --first-account` и `node apps/desktop/scripts/flow-engine-check.mjs`. Последний запрещает генерацию и запускает другой движок только на отдельном профиле. `flowSummary` теперь включает состояния очереди для безопасного перезапуска приложения.

## Flow восстановлен: подтверждённый итог

Причина найдена сравнением с работающим расширением: скрытый runtime Gold успешно загружал legacy-клиент `labs.google`, но разрешал его frontend-миграцию на `flow.google.com`; именно новый shell возвращал `unsupported-country`. Это не было отказом image API или SOCKS5. Диагностика с остановкой только этого перехода показала legacy-страницу со статусом `AVAILABLE`, списком проектов и готовой `grecaptcha.enterprise`.

Исправление ограничено скрытым служебным runtime: при уже загруженном `labs.google/.../tools/flow` переход на `flow.google.com` удерживается. Видимое окно входа/ручного открытия остаётся обычным и может переходить на новый домен. Региональная защита `no-retry` сохранена на случай реального попадания runtime на `unsupported-country`.

Реальная проверка `captures/flow-legacy-runtime-generation-20260906/report.json`:

- оба сохранённых аккаунта использовали разные persistent partitions и отдельные локальные SOCKS-мосты;
- оба показали ожидаемый внешний IP прокси, cookie-isolation прошла;
- аккаунт 1 создал и скачал PNG 690253 байта;
- аккаунт 2 создал и скачал PNG 763539 байт;
- для каждого сохранён remote image job, повторное скачивание совпало по SHA-256 и не выполняло второй generation POST;
- оба изображения визуально проверены: корректные реалистичные автомобильные интерьеры 16:9, без текста, логотипов и коллажа;
- выполнены ровно две разрешённые тестовые генерации — по одной на аккаунт.

Отдельная проба `captures/flow-created-project-route-20260906/report.json` доказала, что старый адрес вида `/fx/project/{id}/tools/flow` из расширения теперь отвечает 404; production на него не переведён. Один диагностический проект `Gold Work Studio route probe` создан без image/video generation и оставлен в аккаунте, чтобы не удалять внешние данные без отдельного действия пользователя.

Целевые Flow/proxy/pipeline тесты после исправления: 43/43; desktop typecheck прошёл. Полный набор: **209/209** (desktop 184, core 19, Remotion 6). Production build: `20260906T104300Z-7589cbb03b-dirty`.

После последующих улучшений сценария, Stock, Remotion и пула Flow общий набор составляет **234/234** теста. Текущая запущенная production-сборка: `20260906T120659Z-7589cbb03b-dirty`; оба настроенных Flow-аккаунта после перезапуска имеют статус `ready`. Backend атомарно запрещает шестой профиль, а интерфейс показывает счётчик `N / 5`. До пяти Flow-изображений могут создаваться одновременно на пяти свободных аккаунтах; на одном аккаунте всегда выполняется не более одной платной операции, переполнение получает первый освободившийся профиль. Проверка выполнена на заглушках без новых Flow-генераций и расходования кредитов.
