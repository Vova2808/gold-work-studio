## Почему перестало работать

Старый `labs.google/fx/tools/flow` перенаправляет на `flow.google.com`. Новый публичный клиент использует Angular/Google RPC и браузерную сессию вместо прежнего NextAuth/Bearer API. Исправление только входа не обновляло генерацию: приложение явно блокировало неподдерживаемый протокол. Дополнительно готовые файлы теперь могут находиться на CDN `flow-content.google`.

## Реализовано

- `flow-rpc.ts`: текущий wire-контракт и разбор framed/XSSI-ответов; создание проекта, модели/доступ, загрузка референсов, изображения, Veo text/start/start+end, чтение media.
- `flow-auth-service.ts`: запросы внутри авторизованного окна выбранного аккаунта; исходный прокси и сессия сохраняются. Используется штатная reCAPTCHA самого проекта; настройки безопасности не меняются.
- `flow-client.ts`: отдельный modern-путь, receipt до скачивания, продолжение по известному media ID, проверка типа скачанного файла и разрешённых HTTPS-хостов. Неопределённый платный запрос не повторяется автоматически; явный отказ не считается успешной генерацией.
- Модели читаются из текущей конфигурации. Для Veo выбирается разрешённый вариант внутри запрошенного семейства по generation tier из credits field 4, режиму и формату. Название подписки — не generation tier. Неподдерживаемые варианты отклоняются до отправки.
- Проверка подключения остаётся read-only и не выдаётся за пробную генерацию.
- RPC IDs: models HTrJv, credits nzlxg, createProject jHPbke, upload maseQ, image ogiZ0b, getMedia as29s, video text YhhmEf / start eb1hJf / start+end nprQif.

## Повторный вход подтверждён, но «Проверить» снова требует вход — 2026-09-13 вечером

Журнал mu06s5vy-27088: успешные flow.session.confirmed при входе в 19:12:29Z и 19:14:45Z; последующие flow:test за 5 и 75 мс возвращают FlowLoginRequiredError без нового RPC. Причина воспроизведена в настоящем Electron на синтетическом HTTPS Flow: скрытая runtime-страница открыта до входа, её WIZ_global_data остаётся анонимной, хотя отдельное login-окно уже подтверждает авторизацию. Общие cookies сами не обновляют JavaScript-состояние ранее открытой страницы.

Исправление: перед needs_login скрытая страница один раз загружается заново при отсутствии данных входа/HTTP 401, затем повторяется только read-only проверка сессии. Отказ доступности/региона, сеть и платные generation RPC не повторяются. После подтверждения cookies сбрасываются на диск. flow.session.reloading/failed содержат тип окна, безопасный адрес, признак перезагрузки и вложенную ошибку; flow:test теперь связан с accountId. Диагностика различает отсутствие входа и отсутствие служебных данных у уже открытого аккаунта. UI не объявляет готовым возвращённый незавершённый login.

flow-session-refresh-smoke.ts: до исправления воспроизводит ошибку сразу после автоматического закрытия login-окна; после — проходит вход → проверка скрытого окна, две одновременные проверки с одной перезагрузкой, настоящий logout и явный отказ без бесконечного retry/удаления аккаунта. 11 профильных unit/diagnostics проверок прошли. Реальный аккаунт проверяется отдельно; первая попытка копирования его cookie-БД остановлена блокировкой открытого приложения (ERR_SQLITE_ERROR), это не ответ Google.
