# Пакет 03. Сохранность очереди и платных заказов

## Изменения

- `FileTaskRepository` раньше принимал произвольный JSON-массив и возвращал `[]` при ошибке разбора или неизвестном корневом формате. Инициализация конвейера после этого записывала пустую очередь. Теперь репозиторий проверяет форму записей, уникальность ID и данные восстановления, сохраняет исходный файл на месте и отклоняет запись. Старт показывает штатное окно с причиной и путём к файлу до подключения IPC очереди и таймера выполнения. Корректные записи сохраняют добавочные поля, пропущенные поля старого формата дополняются прежней логикой загрузки. Запись очереди использует сброс временного файла на диск и атомарную замену.
- Полная очистка останавливается до отмены задач и изменения проектов, если медиа-задача выполняется или есть данные незавершённой платной операции. Очистка завершённых сохраняет защищённые запуски и их необходимые записи зависимостей. Запуск заново, перегенерация сцены и пересборка проверяют, какие сохранённые задачи будут вытеснены. Границы общей озвучки включают все её сцены. Штатное продолжение Stock переносит только совпадающий заказ Lumean с прежним отпечатком текста и голоса.
- При сохранённом ID карточка предлагает «Продолжить заказ» для ошибочной или остановленной задачи, если её повтор разрешён. Flow скачивает или опрашивает прежнее задание даже после смены настроенного видеопровайдера. Lumean использует сохранённый ID и сверяет текст и голос. При сбое сохранения полученного ID приложение удерживает его в памяти, а прежний маркер на диске защищает от новой отправки после аварии.
- Очередь фиксирует начало задачи до её исполнения. Платные медиа-вызовы AnyModel и Google AI Studio сохраняют маркер перед созданием. Явный отказ в создании или доказанный сбой соединения с прокси до отправки разрешает штатную обработку отказа. Обрыв соединения, неоднозначный ответ или сбой загрузки без сохранённого ID сохраняют блокировку. Очередные платные медиа-POST AnyModel используют одну транспортную попытку и запрещают перенаправление. Выбранный Edge TTS определяется по фактической модели и сохраняет прежнее поведение. Для AnyModel video и классического Google Veo сохраняются данные уже существующих GET-маршрутов до polling. Ключи и подписанные ссылки не добавляются в очередь.
- Старые начатые `image`, `video` и `speech` без маркера или ID остаются видимыми с неизвестным результатом. Версия отслеживания 1 охватывала Flow и Lumean, но не записывала исторический маршрут задачи. Текущий провайдер не подтверждает исходную отправку. Версия 2 отмечает работу, начатую новым конвейером. Завершённые задачи и свежие задачи без признаков начала проходят обычную загрузку. Существующие сценарии восстановления v1 в `flow-pipeline.test.ts` и `lumean-recovery.test.ts` описывают прежнее разрешение автоматического продолжения по текущему провайдеру. Тестовые файлы сохранены.

## Ручная сверка без создания заказа

Пользователь выполняет эти действия после сборки на отдельной копии профиля при отключённой сети. Рабочий профиль и исходная копия очереди нужны для сверки.

1. Открыть копию с корректным пустым `queue.json`. Очередь открывается пустой. На отдельной копии с оборванным JSON или объектом вместо массива ожидается ошибка запуска с путём к `queue.json`. Сравнить файл с копией до запуска. Его содержимое и имя сохранены.
2. Если есть сохранённая запись с `pendingSubmission` без ID, открыть профиль с этой записью и выбрать «Очистить всю очередь». Должна появиться причина блокировки, запись остаётся. После «Очистить завершённые» и повторного открытия должны сохраниться маркер и отсутствие действия повторной отправки.
3. Если есть сохранённая ошибка скачивания или остановленная задача с известным ID, открыть её карточку. Проверить наличие «Продолжить заказ» и сохранность ID после попытки очистки. Для проверки интерфейса нажимать продолжение не требуется.

## Границы

- Очередь хранит ID, которые приложение успело получить и сохранить. Старые несохранённые ID и синхронные ответы без пригодного для polling ID требуют сверки у провайдера. Для повторного чтения известного видео-заказа нужен доступ к исходному сервису и аккаунту. Старая версия приложения не понимает новые поля восстановления, поэтому для неё нужна отдельная копия профиля.
- Файлы `queue.json.corrupt-*`, оставшиеся от прежнего поведения, можно использовать для ручной сверки. Программа не выбирает их автоматически, так как старый файл может не соответствовать текущим проектам и заказам. Проверка текущего файла перед записью выполняется в одном процессе студии. Внешняя подмена файла во время записи не поддерживается.
- Остановка, удаление и обновление приложения относятся к пакету 04. Разбор не подтверждает восстановление производственного процесса и живое поведение API. Для 03 требуется пользовательская ручная приёмка.
