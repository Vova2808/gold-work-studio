# Пакет 07 — отсутствующий Desktop API

По коду подтверждено: App и его дочерние компоненты выбирали `window.goldWork ?? fallbackApi`. Если preload не предоставлял настоящий IPC, обычная точка входа продолжала показывать имитационные проекты, задания и результаты. Это скрывало реальную неисправность запуска.

Точка входа теперь допускает App только при наличии bridge. Отсутствие bridge вызывает существующий ErrorBoundary с понятной причиной и способом запуска. Имитационный API и старые fixture-файлы сохранены; стандартный вход в программу до них не доходит. Ошибки уже существующего IPC по-прежнему передаются обработчикам ошибок, не заменяются демонстрационным успехом.

Выполнены только статический разбор и редактирование; тесты/проверочные команды/сборка/приложение не выполнялись, новых тестов нет. Независимое ревью и пользовательская приёмка требуются.

Ручная проверка: штатно запустить собранную версию через постоянный START и убедиться, что открывается настоящий E-профиль с собственным проектом. Если появляется сообщение об отсутствии связи, дальше производство не запускать: прислать сообщение и Build ID, исправить сборку/запуск. При этой ошибке интерфейс не должен показывать демонстрационные успешные подключения или готовые ролики. Специально ломать preload для проверки не требуется.
