# Реестр проектов: память и сохранение — 03.10.2026

## Результат и границы

Общий JSON остаётся совместимым с прежними версиями, резервными копиями и инструментами. Нет миграции, удаления кандидатов или нового формата sidecar. При холодном чтении индексируются границы проектов, в кэше остаются данные для интерфейса. Полный список кандидатов читается по требованию для одного проекта. При сохранении неизменённые проекты копируются из исходного файла блоками, без повторного JSON.stringify всех старых кандидатов.

Это снижает нагрузку хранения. **Скорость поиска, пригодные 5 фото + 5 видео, устойчивость за ночь и полный 18-минутный Final за 2–3 часа пока не подтверждены.** Никаких новых AnyModel/озвучка/Flow-запросов в этой проверке нет.

## Сохранность и проверки

- В итоговом опыте оба результата сверены со всеми полями исходных 35 проектов, включая каждый массив кандидатов, выбранные материалы, пины и контрольные точки: полное deepEqual. Изменение заголовка в копии после четвёртой записи возвращено к исходному.
- Все 246 указанных файлов оплаченной озвучки мотоциклетного проекта существуют. Исходники/голоса не изменялись.
- Основной реестр не менялся: SHA256 `cc92203aa3a1ec2da78e24aa15f1fcfce249cc6d1756baf6b4d523aec015e8ad`.
- 12 различных адресных тестов прошли: репозиторий (5), JSON (2), проекция (1), корзина (1), staged selection (3). Покрыты UTF-8/экранированные скобки через границы блоков, конкурентное первое чтение, чужая правка во время сохранения, отложенные кандидаты и выброшенная updater-ошибка. Повреждённый/обрезанный JSON больше не превращается в пустой реестр для последующей записи: исходный файл остаётся на месте, выдаётся ошибка восстановления.
- Реестр сохраняется через временный файл и rename; для него отключён прежний неатомарный copy fallback. На Windows собственный читающий дескриптор закрывается до rename. Изменение другим процессом, замеченное до замены, останавливает запись. Это не распределённая блокировка и не доказательство поведения при отключении питания.
- Desktop typecheck/build прошли. Сборка `20261003T103458Z-749e713a76-dirty`; изолированный startup exit0, main/renderer buildId совпали. При закрытии остаётся ранее известное предупреждение GPU `WaitForGetOffsetInRange`; оно не объявляется устранённым. Полная suite не запускалась, четыре ранее описанных legacy automation failures не перепроверялись.
