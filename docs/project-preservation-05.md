# Пакет 05 — сохранность редактирования

База: E-M1-L1, a79feca67d4df6f1873032999478d5bac681b3d2. Изменения подготовлены координатором в отдельном worktree project-preservation. Только чтение, редактирование и статический разбор; приложение, сборка, проверки и провайдеры не запускались. Независимое ревью и ручная приёмка ещё требуются.

## Подтверждённые причины и изменения

- IPC `projects:update` передавал полный список сцен/настройки без проверки версии исходного черновика. Проверка `expectedUpdatedAt` теперь происходит внутри сериализованной мутации реестра. Метка изменения монотонна даже при двух изменениях в одну миллисекунду. Поле проверки не сохраняется в проект. Устаревший payload не повторяется автоматически: UI получает свежий проект, существующее трёхстороннее объединение сохраняет местные правки, пользователь повторяет сохранение после просмотра.
- Редакторы проекта, сценария и timeline передают версию своего черновика. Ответы операций с героем используют версию возвращённого проекта. Старые ответы polling/сохранения не заменяют более свежую версию в UI. Изменения, внесённые во время сохранения, остаются в редакторе; такое сохранение не разрешает немедленный уход. Ошибка сохранения timeline оставляет правку для повторного сохранения или Undo.
- Обычное сохранение metadata не обновляло `project.json`. Успех IPC теперь возвращается после существующей атомарной durable-записи `project.json` и `scenario.json`. Последовательный writer читает актуальный полный реестр, повторяет запись при новой версии, не заменяет свежий backup старым аргументом вызывающего кода. Ошибка backup явно отличается от ошибки записи реестра; уход из редактора повторяет незавершённое сохранение backup без повторной отправки старого payload.
- Обычное закрытие окна не вызывало уже существующие guards редакторов. Main теперь запрашивает разрешение renderer, который сначала сохраняет черновики проекта/сценария/timeline. Ошибка оставляет окно открытым. Если renderer не отвечает, доступно явное нативное решение; таймаут сам по себе ничего не разрешает. Завершение фоновых сервисов перенесено на `will-quit`, чтобы отменённое закрытие не отключало работающее приложение.

События закрытия сверены по официальным [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window#event-close) и [app](https://www.electronjs.org/docs/latest/api/app#event-will-quit). Никакого исполнения Electron при этой сверке не было.

## Ручная проверка пользователем

1. На копии рабочего проекта изменить название/настройку голоса, сохранить, закрыть и снова открыть. Должны сохраниться выбор и настройка. В `project.json` папки проекта должны быть последние сохранённые поля.
2. В сценарии изменить текст, закрыть приложение крестиком без отдельного нажатия «Сохранить», открыть снова. Правка должна сохраниться. Повторить с настройкой проекта и изменением timeline. При ошибке сохранения окно должно остаться открытым с сообщением.
3. При обычной работе фонового процесса оставить черновик открытым. Свежие пути озвучки/материалов не должны исчезать после сохранения. Если появилась ошибка версии, проверить оставленный черновик и сохранить повторно; автоматического затирания не должно быть.
4. При медленной записи продолжить правку: новая правка должна оставаться несохранённой до следующего сохранения; закрытие не должно молча отбросить её.

## Границы

Это защита обычного сохранения и закрытия редакторов проекта, сценария и timeline. Принудительное завершение процесса, авария renderer или Windows не дают выполнить асинхронное сохранение несохранённого черновика. Работа очереди при паузе/остановке/закрытии/обновлении — пакет 04; этот пакет не подтверждает полное восстановление производства или результат рендера. Изменения модели/провайдера и оплаченные операции не выполнялись.
