# Подбор: пустой анализ и продолжение сохранённой работы

Подготовлено к независимому статическому ревью. Исполнение, сборка и ручная приёмка не выполнялись.

Подтверждённая цепочка по исходникам: SSE с завершающим событием без извлечённого текста вызывает `AnyModelOutputFormatError` с подтверждённым завершением транспорта. Обработчик визуальной проверки прежде возвращал искусственный uncertain-result и сохранял его как `complete`; внешний измеритель поэтому записывал успешное завершение этапа анализа. Это не доказывало пригодность кандидата: последующий review оставался uncertain. Но техническая причина могла попасть в обычный `searchRecovery.reason` и получить классификацию отказа по содержимому.

Исправление в `documentary-intelligence.ts`: пустой завершённый визуальный ответ сохраняется с `state: rejected`, `rejection: empty-response`, исходными binding/model/completion и временем завершения. Выбрасывается `DocumentaryAnalysisError` (`kind: pending`, `purpose: visual-illustration`); успешный результат анализа не возвращается. Та же оплаченная попытка автоматически не повторяется. Прежний `complete/uncertain` распознаётся только по совокупности структурных признаков: `completion.disposition: empty`, ноль полученных символов, пустой `raw`, `result.status: uncertain`. Другие uncertain-ответы остаются самостоятельными результатами модели. Пригодный полученный `received/raw` по-прежнему разбирается локально существующим checkpoint reader, затем проходит прежние проверки текущего задания.

Подтверждённый разрыв продолжения в `documentary-project-service.ts`: отображаемый проект загружается с `omitCandidates`, а подготовленный через `apply(commit=false)` оригинал и source-manifest сохраняются на диске до принятия сцены. При остановке эти данные могли оставаться вне выбранного материала сцены; обычный следующий проход начинал новый поиск.

Продолжение теперь читает сохранённый shortlist один раз и предлагает его прежнему пути выбора до запуска ленивых поисковых генераторов. Для локальных оригиналов используются scene source-manifests, наличие файла и проверка его ожидаемого checksum в `apply`. Новые manifests получают `selectionBinding` задания: исходная реплика, requirement, контекст сцены, формат и layout. При изменении задания такая подготовка не считается продолжением. Legacy-manifest без binding допускается только как неподтверждённый кандидат из текущего сохранённого shortlist. Он не передаёт одобрение: платный ответ всё равно должен совпасть по прежним checkpoint/task/file/range/model guards. Разные файлы одного источника сохраняют собственную проверку checksum.

Границы сохранены: готовая неизменённая озвучка и принятые материалы используют прежний путь; новые ответы не объявляют неподготовленную сцену готовой. Проверки объектов, людей, событий, географии, качества и реального видео не ослаблены. Pending/partial и неопределённые платные запросы, rejection/uncertainty caches, бюджеты, таймауты, параллельность и явное разрешение оплаченного повтора не расширены. Новых зависимостей нет.

Координатор добавил полную классификацию незавершённых сцен, приоритет технической причины перед совпадением searchRecovery, отдельную диагностику material-selection и снимок причин/следующих действий в существующем stockProduction. UI явно показывает, что это причины на момент последней остановки, а не одобрение текущего материала. Учитываются все категории, включая no-results/cdn/invalid-key/unknown, и все незавершённые сцены, даже без записи в исходном массиве failures. Последующие обычные обновления процесса заменяют старый снимок. Защита неполного/устаревшего Final не снимается.

Ограничение продолжения: legacy shortlist не доказывает историческое задание; его элементы входят только как неподтверждённые кандидаты и проверяются по актуальному заданию. После исчерпания пригодного сохранённого пула discovery может продолжиться в прежних пределах. Повтор download/review известных отказов и неопределённых запросов блокируется прежними caches/guards; полное отсутствие повторных поисковых обращений между ручными запусками не обещается.

Без сырого SSE нельзя установить, почему провайдер не прислал извлекаемый текст: upstream не сформировал ответ либо использовал неподдерживаемое поле. Переписывание парсера по одним счётчикам не обосновано. HTTP 200 и terminal подтверждают завершение транспорта, не полноту визуального анализа и не отсутствие списания.

Статически просмотрены: fresh terminal-empty, старый empty receipt, обычный uncertain verdict, пригодный received/raw, повторное открытие неизменённого shortlist, подготовленный локальный файл, checksum mismatch, изменённое задание, legacy-manifest, pending/partial guards и ленивый запуск discovery после сохранённой партии. Это чтение исходников и diff, не результат исполнения. Пользователю остаётся подтвердить продолжение существующего проекта, повторное использование неизменённых результатов и конкретные причины действительно незакрытых сцен.
