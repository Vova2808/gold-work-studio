# №08. Продолжение Stock Documentary

Рабочая ветка `codex/production-resume-20261110`, база `cb659e53c9879cc56c246fb6863b00794b9b164b`. Изменения подготовлены по исходникам. Сборку, запуск и ручную приёмку выполняет пользователь.

## Что изменилось

- Планирование допускает текущую очередь, когда её активная работа состоит только из озвучки. После плана используется та же очередь. Пауза продолжается с сохранёнными задачами, а работающие и ожидающие задачи сохраняют ID и состояние. Незавершённый известный заказ Lumean проходит прежнюю проверку входов. Запрос с неизвестным результатом сохраняет блокировку повторной отправки.
- Отдельная постановка озвучки меняет только сцены, для которых поставлена задача. Готовые MP3 старого формата используются повторно. Новый сценный MP3 получает неизменяемое имя с хешами входа и содержимого. Сохранённое изменение текста или настроек голоса сбрасывает привязку устаревшего звука при проверке ревизии проекта. Сам файл остаётся на диске. Общая дорожка по-прежнему зависит от состава, порядка и текста входящих в неё сцен.
- Если у автоматически принятого материала пропал файл, в подбор возвращается эта сцена с сохранёнными источником и свидетельством проверки. Пропавший вручную закреплённый файл требует решения пользователя. Кадр с обновлённым AI-планом может сохранить одобрение, если визуальное задание совпадает и прежнее свидетельство подходит текущему контексту.
- Готовый тайминг переиспользуется. Если во время измерения меняется озвучка, длительность или нормализация, расчёт для прежнего снимка не сохраняется поверх свежих данных.

При интеграции независимый рецензент нашёл несовместимость новой защиты с явной заменой отдельного звука в старом режиме общей дорожки. Координатор исправил её в `3bf0fb6`: задача с `scope=scenes` сохраняет прежние звук/диапазон до успешной атомарной привязки нового файла. Неизменённая общая дорожка с готовыми отдельными заменами также переиспользуется. Восстановление завершённых задач не возвращает старый звук поверх текущей привязки.

Кеши планов, материалов и ответов, ограниченные допоиски и защита оплаченных заявок продолжают работать по своим контрактам. Хеш контекста AI-плана учитывает весь сценарий. Правка общего контекста может потребовать получить актуальный план для нескольких сцен. Сохранённый исходник проверяется по новому заданию и текущим свидетельствам. Для старых отдельных MP3 без метаданных исходный текст и голос задним числом подтвердить нельзя. При ручном экспорте и при восстановлении последней операции также важны правки №09.

## Ручная проверка объединённого кандидата

1. Открыть сохранённый Stock-проект с готовыми MP3, принятыми кадрами и незавершённым подбором. Продолжить производство. Готовые сцены должны сохранить файлы и ручные настройки. Новая озвучка нужна только для отсутствующих или изменённых реплик. Подбор должен продолжиться с незавершённых сцен и сохранённых ответов.
2. Если в существующей очереди есть поставленная на паузу озвучка, после повторного открытия продолжить проект. В очереди должны остаться те же задачи. Для известного незавершённого заказа ожидается продолжение работы с его ID.
3. Если по работе требуется изменить одну реплику сохранённого проекта, ожидается сброс только её привязки к отдельному MP3. Остальные MP3 и принятые материалы с прежними заданиями сохраняются. При наличии общей дорожки изменение реплики затрагивает общую привязку. Явная замена звука отдельной сцены в старом проекте должна сохранять прежний звук до успеха. Специально создавать платную операцию для этого пункта не требуется.
4. При действительно пропавшем файле автоматически принятый кадр возвращается в подбор. Вручную закреплённый остаётся закреплённым, а автоматический запуск сообщает о проблеме с файлом. Удалять рабочие файлы ради этой проверки не нужно.

Зафиксировать Build ID, действие, номера затронутых сцен и результат. Пакет остаётся в ожидании ручной приёмки.
