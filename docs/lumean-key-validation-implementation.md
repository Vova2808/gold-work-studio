# Lumean: проверка API-ключа перед записью и запросом

## Подтверждённый случай

В сборке `20261110T193610Z-dec09c9839` сохранение настроек Lumean завершилось в `20:08:08Z`. Затем проверка подключения дала четыре локальные ошибки ByteString без HTTP-ответа. Код принимал значение ключа при сохранении, а преобразование значения `X-API-KEY` в HTTP-заголовок происходило в транспорте. Повторы считали этот отказ сетевой ошибкой. Ключ и профиль при разборе не читались.

## Изменение

- `voicer-api-key.ts` задаёт общую проверку значения HTTP-заголовка. Она отклоняет DEL, кодовые единицы выше `U+00FF` и управляющие C0 за исключением TAB. Внутренние пробелы, TAB и байты `0x80–0xFF` допустимы. Длина и префикс ключа не проверяются.
- `voicer-store.ts` сохраняет прежний `trim()` по краям и проверяет непустой ввод перед шифрованием. При отказе файл настроек сохраняет прежнее содержимое. Пустой ввод по-прежнему оставляет прежний ключ.
- `voicer-client.ts` проверяет сохранённое значение перед прямым или proxy-запросом. Ошибка содержит фиксированный текст без значения ключа, фрагмента, позиции или кода символа. Тип ошибки — `configuration` с `retryable: false` и `creationUncertain: false`. Транспортная валидность сама по себе не подтверждает авторизацию. Ответ HTTP 401 по-прежнему обрабатывается отдельно.
- Новый заказ проверяет ключ перед отметкой о платной отправке. Запрос повторно читает и проверяет актуальный ключ перед транспортом. Если конфигурация стала непригодной после отметки, существующий `onOrderRejected` снимает отметку этого запроса при определённом локальном отказе. Возобновление известного заказа проходит через существующую обёртку `orderKnown`. При калибровке чтение готового кэша и предупреждение о прежней неопределённой отправке остаются перед проверкой ключа для нового запроса.

## Статическая сверка и ручная проверка

По исходникам прослежены сохранение через `voicer:save-settings`, вывод ошибки в настройках, проверка через `GET /user`, загрузка шаблонов и восстановление озвучки через очередь или калибровку. Выполнялось только чтение исходников и Git diff. Тесты, приложение, сборка и запросы не запускались.

В новой сборке при наличии ранее сохранённого непередаваемого ключа нажмите «Проверить» в разделе Lumean. Должно появиться сообщение о недопустимых символах без повторов сетевой ошибки. Затем можно ввести заведомо тестовую строку с кириллицей и нажать «Сохранить». Ожидается тот же текст, ранее сохранённый ключ остаётся в хранилище. Скопируйте действующий ключ из кабинета Lumean, сохраните его и один раз нажмите «Проверить». Для этих действий достаточно настройки подключения. Голосовые образцы и платные заказы не требуются.
