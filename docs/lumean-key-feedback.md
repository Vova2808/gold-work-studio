# Сохранение и проверка настроек Lumean

В сборке `20261110T193610Z-dec09c9839` кнопка «Проверить» читает сохранённые настройки. Раньше она оставалась доступна и при заполнении нового ключа, proxy или Base URL. Пользователь подтвердил, что в случае с HTTP 401 сначала нажал «Сохранить» и получил подтверждение. Причина этого ответа после сохранения пока не установлена.

Форма блокирует проверку, пока есть черновик, и показывает порядок действий. При редактировании прошлый результат исчезает. Успешное сохранение сбрасывает отметку о предыдущей проверке. Во время операции поля недоступны для редактирования. Если сохранение завершилось ошибкой, черновик остаётся в форме. Проверка по-прежнему читает сохранённые настройки.

## Что установлено для присланного 401

В существующем журнале той же сессии сохранение `voicer:save-settings` завершилось успешно в 19:51:11.948Z (22:51:11 по Москве), затем `voicer:test` получил HTTP 401 в 19:51:16.308Z. Путь клиента: GET `/api/public/user`, сохранённый ключ в `X-API-KEY`, сохранённый proxy. Base URL соответствует HTTPS `api.lumean.app/api/public`, без query; наличие зашифрованных ключа и proxy подтверждено без расшифровки и вывода значений. HTTP CONNECT ошибки этого транспорта идут через `network.failed`; в данном фрагменте записан обычный HTTP response 401. Это не устанавливает причину отказа ключа на стороне сервиса.

Прежний клиент затирал конкретное сообщение ответа общей фразой о ключе. Теперь только три фиксированных сообщения из [официальной документации](https://lumean.app/en/developers/docs/guide/authentication) преобразуются в безопасные причины: `missing_key`, `invalid_or_inactive_key`, `expired_key`. Неизвестное сообщение, другой язык или другой формат даёт `unspecified`; содержимое ответа не выводится. Событие `voicer.auth.rejected` содержит только фиксированный endpoint без параметров/идентификаторов, status, reason и responseFormat. Произвольный текст сервера, ключи, их отпечатки, аккаунты и proxy в него не копируются.

Авторизация, маршрут, настройки аккаунта, endpoint проверки, пагинация шаблонов и создание/повторы заказов не изменены. Новая версия проясняет отказ, но пока не считается устранением наблюдавшегося 401. Подписка, права и неверный proxy не объявляются его причиной без подтверждения.

## Ручная проверка

1. Откройте «Настройки» → «Lumean» и введите ключ, который намерены сохранить. Появится подсказка, а кнопка «Проверить» станет недоступна.
2. Нажмите «Сохранить» и дождитесь подтверждения. Для сохранённого ключа кнопка «Проверить» снова доступна, прежний результат проверки скрыт.
3. Один раз нажмите «Проверить» и зафиксируйте результат. Если снова появится 401, достаточно сообщить Build ID и текст ошибки. Озвучку и создание заказов для этого сценария запускать не требуется.
