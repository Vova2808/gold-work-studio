# Пакет 04. Остановка, удаление и закрытие

## Очередь

- Пауза прекращает выдачу новых задач. Работа, которая уже выполняется, занимает слот до выхода, включая отдельный слот видео. Статус `retry_wait` учитывается при закрытии, удалении и установке обновления.
- «Остановить» приостанавливает планирование и ждёт завершения текущих записей. Если исходная платная отправка ещё ждёт ID или синхронный ответ, остановка может занять время до ответа или таймаута. Когда ID записан, ожидание результата можно прервать с сохранением ID. Запуск, продолжение и повтор той же очереди блокируются до окончания остановки.
- У завершившейся задачи сохраняется готовый результат. Задача со статусом `cancelled` и сохранённым ID продолжает исходный заказ через существующий путь восстановления. При неопределённом исходе создания сохраняется блокировка повторной платной отправки. Очистка очереди отказывает, пока выполняется любая задача, в том числе локальная сборка.

## Удаление и установка

- Перенос проекта в корзину проходит под общей блокировкой операций. Уже начатый подбор, подготовка сценария, производство, импорт и другие учитываемые операции дают отказ до переноса. Очередь проверяет возможность удаления, затем реестр и папка переходят в корзину, после чего записывается очередь без удалённого проекта. При сбое после переноса приложение пытается вернуть проект и показывает ошибку возврата, если он сорвался. Корзина и очередь остаются отдельными файлами, поэтому аварийное завершение процесса между записями может потребовать восстановления из корзины.
- Обычное закрытие при работе очереди предлагает дождаться завершения или остановить задачи и дождаться записи результатов. Проект на паузе без выполняющихся задач сам по себе закрытию не мешает. Редактор подтверждает сохранение черновика и резервной копии через существующий запрос закрытия. При молчании редактора обычное закрытие требует отдельного явного выбора. Ошибка сохранения или продолжающаяся операция оставляет окно открытым.
- Установка загруженного обновления использует то же подтверждение черновика, затем держит редактор и операции заблокированными до выхода. При отказе или таймауте подтверждения установка отменяется, а редактор разблокируется. При отказе запуска установщика, который ещё можно наблюдать из работающего Electron, приложение снимает блокировку и оставляет загруженное обновление доступным. Поздний сбой дочернего установщика после выхода Electron лежит за пределами этого подтверждения.

## Ручная приёмка пользователем

1. На копии проекта изменить сценарий или монтаж и закрыть окно. После повторного открытия сверить правку. При ошибке сохранения окно должно остаться открытым, а редактирование снова доступно. Повторный крестик во время подтверждения должен относиться к тому же запросу.
2. Во время локального импорта библиотеки попробовать закрыть окно и удалить проект на отдельной копии данных. Дождаться отказа без перемещения проекта и завершения импорта, затем повторить на этой копии. Успешное окончательное удаление из интерфейса очищает корзину, как указано в диалоге.
3. На отдельной установленной сборке Windows с уже загруженным обновлением проверить установку с черновиком. При ошибке сохранения версия остаётся прежней, после успешного сохранения правка должна быть доступна в новой версии. Этот сценарий касается установщика приложения и обходится без оплачиваемых запросов.
4. Пауза с действующим слотом и остановка с ID относятся к состоянию существующего заказа. Для ручного подтверждения использовать уже начатую операцию в рамках отдельной пользовательской приёмки.

Подготовленный diff разобран статически. Сборка, запуск и ручная приёмка остаются за пользователем.
