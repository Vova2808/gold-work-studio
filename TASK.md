# Gold Work Studio — актуальное задание

Редакция пользователя: 2026-11-09. Этот файл хранит общую цель, а STATUS.md — фактическое состояние. Новые прямые указания пользователя имеют приоритет. Менять цель и обязательные условия можно только по новым указаниям пользователя.

Канонические живые файлы координатора: E:\GoldWorkStudio\TASK.md и E:\GoldWorkStudio\STATUS.md. Копии в репозитории фиксируют состояние передачи; проверяемые пользователем source/profile остаются неизменными, журнал координатора обновляется отдельно.

## Общая цель и завершение

Перенести актуальную версию с D: в E:\GoldWorkStudio без старых роликов и ненужных результатов. Сохранить нужные исходники, локальные изменения всех участников, настройки, данные восстановления, контрольный проект, имеющуюся озвучку и принятые материалы. Затем довести всю программу до рабочего состояния, подтверждённого личной ручной проверкой пользователя.

Окончательное завершение — пользователь подтвердил конкретную итоговую версию: запуск с E:, открытие/сохранение проекта, закрытие и повторное открытие, основные функции, остановку/продолжение, полный производственный процесс и итоговое видео. Зафиксировать принятый коммит и ограничения. Подготовленный код сам по себе не означает приёмку.

## Полный запрет исполнения для Codex и всех агентов

Не запускать unit/integration/smoke/E2E-тесты, тестовые/проверочные скрипты, test/check/lint/typecheck и аналогичные проверки, сборку/упаковку, приложение/dev-server/preview, генерации/пробные запросы к провайдерам, производственный поиск, экспорт/рендер/сборку роликов, бенчмарки/контрольные прогоны. Не выполнять это под другими названиями. Не создавать новые тесты; существующие сохранить.

Разрешены чтение/редактирование файлов, статический разбор исходников и diff, чтение существующих журналов, файловые операции, сверка перечней/размеров при переносе и Git. Исторические проверки не являются проверкой новых изменений. Сборку, запуск, производственные операции, измерения и приёмку выполняет только пользователь.

## Организация и модели

Пользователь общается с главным координатором. Координатор сохраняет цель, распределяет ограниченные задачи, контролирует исполнителей, ревьюит фактические diff, объединяет подходящие изменения, готовит отдельную версию и фиксирует ручную обратную связь.

Независимые задачи выполнять в реальных отдельных агентских сессиях, до трёх рабочих агентов при поддержке среды. Каждому: цель/границы, реальный ID, фактическая модель/effort, окружение, репозиторий, исходный коммит, отдельные ветка и worktree, владение файлами, результат, прямой запрет всех запусков. Общие файлы заранее закрепить за владельцем. Не дублировать работу исполнителя. Подтверждать доступ агента к локальному E:.

Желаемые настройки: координатор GPT-6 Astra High; исполнители GPT-6.1 Sol High; сложные ошибки состояния/платных операций и независимое критическое ревью GPT-6 Astra Extra High; простые задачи при необходимости Sol Medium. Применять только поддерживаемыми механизмами; сообщать реальные значения и ограничения. Не утверждать переключение без подтверждения. Если переключение координатора требует пользователя — дать одну точную инструкцию.

## Сохранение работы, контекста и Git

TASK.md и STATUS.md обновляет координатор; агенты передают результаты. В начале работы и после восстановления контекста прочитать оба файла, сверить Git/файлы, продолжить незавершённую общую задачу. Последний баг не заменяет общую цель.

Сохранять состояние после завершённых частей. Если счётчик доступен: готовить передачу около 80% контекста и переходить до 90%. Если недоступен — прямо сообщать, не выдумывать процент. Передача: цель, repo/branch/worktree/commit, изменения и новые файлы, статическое ревью, замечания пользователя, следующий шаг. Старое дерево сохранять до подтверждения преемником. Не переносить полную историю без необходимости.

Убрать только ранее добавленное принудительное сжатие после ответа через model_post_turn_compact_threshold_percent, если оно активно. Не завышать контекстное окно. Не заявлять отключение внутреннего сжатия.

Перед commit/push/PR прочитать hooks и workflows. Не допускать косвенного запуска запрещённых действий. Не удалять тесты и не обходить защиты. Если отправка неизбежно запускает проверки/сборку — остановить только отправку, сохранить работу локально и объяснить причину. В GitHub — только необходимые исходники/ресурсы/документация; секреты, пользовательские данные, тяжёлые проекты, кэши и платные журналы — локально.

Порядок: отдельная ветка задачи → diff исполнителя → ревью координатора → независимое статическое ревью критического изменения → отдельный кандидат → ручная проверка пользователя → фиксация приёмки. Коммит/PR: проблема, правка, статическое ревью, что проверить вручную, выполнение Codex не проверялось.

## Этапы

1. Перенос: подтвердить источник D:, сохранить изменения/worktrees, определить состав/размеры, перенести код/ресурсы/настройки/восстановление; контрольный проект отдельно. Разделить source/data/exports/cache. По файлам разобрать старые пути. Старую копию не удалять; подготовить перечень возможной будущей очистки с размерами. До подтверждения: «Файлы перенесены, ожидается ручная проверка».
2. Критические исправления по аудиту: платные отправки, очередь/восстановление, пауза, защита свежих данных, закрытие/остановка/удаление/обновление, копирование/очистка результата, резервный имитационный API.
3. Полный процесс: исправить подбор, сохранение результатов и продолжение по исходникам/имеющимся данным. Сохранить озвучку и принятые материалы. Новые производственные запуски делает пользователь.
4. Основные функции и оптимизация подтверждённых узких мест. Простые правки существующего механизма; новые библиотеки/базы/слои только при необходимости. Не добавлять функции до согласованных исправлений. Удалять дубликаты/обходы только после разбора назначения. Не обещать измеренное ускорение без измерений пользователя.
5. Единый итоговый кандидат и ручная приёмка пользователя; записать принятый коммит/ограничения.
