## Сделано

1. **Исправлена блокировка сцены 78.** `planned-story-timing.ts` перед запуском полного производства пересчитывает длительности по сохранённой калибровке; реплики длиннее 9 секунд делит без потери текста. Актуальный успешный аудит содержания переносится с новым timing fingerprint, а не подделывается для изменённого narration. Pipeline проверяет общий допуск ±5% и только затем сохраняет план. Сток и готовый вставленный сценарий этой миграцией не затрагиваются.
   - На реальном `project_mtt2h2px_5li701i` read-only воспроизведение: сцена 78 стала **7.115 с вместо 5**, весь текст неизменён, максимальный кадр 7.115 с, ошибок длины и актуальности аудита нет. Сам пользовательский проект этой диагностикой не переписан; исправление применяется при следующем запуске.
2. **Новый narration-first путь** для новых AI Story сценариев по промту с калибровкой: литературный план → цельная озвучка → один редакторский проход → детерминированная разбивка → визуальные промты. `narration-writer.ts` не требует писать текст сразу в 156 JSON-сценах с длинными imagePrompt.
   - До 12000 целевых знаков narration пишется одним ответом, отдельно по разделам внутри JSON; более длинные тексты — смысловыми разделами с планом и предыдущим контекстом, не двумя последними репликами.
   - Отдельные требования к объяснению/вымыслу/фактам, хронологии, единым критериям сравнения, конкретным примерам и разговорной речи. Запрещено зачитывать шаблон «ваш сегмент / проблема / главный риск», повторять обещания между разделами и раздувать длину водой.
   - Редактор видит весь narration и требования, возвращает только нужные замены разделов. Непрошедший редактуру или общий хронометраж текст не получает production-ready маркер. Повторных бесконечных редакторских циклов нет.
   - `ReferenceAnalysis.narrationDraft` сохраняет план, текст, результат редактуры и визуальный префикс; `main.ts` записывает checkpoints через guarded mutations. Смена модели не обнуляет этот черновик. Старые незавершённые покадровые черновики продолжаются совместимым прежним путём; новая схема не должна молча уничтожать уже написанные сцены.
   - Готовый пользовательский текст не редактируется. Визуальная разметка использует существующий `prepareReadyScript`, получивший поддержку готового плана и восстановления визуального префикса.
3. **Визуальные промты получают исходные требования к герою**, а не только сокращённую моделью visualBible. Для явно запрещённых split-screen/collage/infographic добавлено точечное исправление только imagePrompt проблемных кадров. Это узкая проверка, не обещание автоматического понимания всех визуальных ошибок.
