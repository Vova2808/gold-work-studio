## 3. Как доводить сценарии до целевых 8–9/10

Дополнительная просьба пользователя перед выключением ПК: зафиксировать улучшение качества для разных тем AI Story. Это **план будущих изменений**, не реализованная возможность. Гарантировать 8–9/10 для любого входного промта нельзя: оценка зависит от темы, исходных данных и аудитории. Цель — стабильное качество по проверяемым критериям, а не автоматическая надпись «9/10» от той же модели, которая написала текст.

### Шаг 1. Одно согласованное задание

До написания зафиксировать: о чём ролик, для кого, какой вопрос закрывает, язык, жанр, голос/измеренную скорость и согласованную длительность. Промт на 3 минуты при настройке 13 минут — конфликт, который нужно явно показать при уже существующем подтверждении длительности, а не молча растягивать текст. Не добавлять новую анкету: брать известные данные из канала, проекта и промта, спрашивать только при существенном противоречии.

Отделить литературные требования от визуальных. Описание лица, одежды героя, художественный стиль и камера не должны раздувать запрос написания narration. В визуальные промты их подставлять позже из одного сохранённого описания. Герой необязателен; если он есть, заранее зафиксировать, говорит он от первого лица или о нём рассказывает другой ведущий.

### Шаг 2. План под жанр, а не одинаковый шаблон для всех

- **Объяснение / услуги / финансы / автомобили:** вопрос → механизм → конкретные примеры → ограничения → сравнение по одинаковым критериям → ответ и практический вывод. Не превращать объяснение в вымышленное расследование.
- **Вымышленная история:** герой и цель → препятствия → решения и последствия → поворот → разрешение. Следить за временем, местом, знаниями и действиями персонажей.
- **Исторический / фактический рассказ:** отделять подтверждённые сведения от реконструкции и авторского предположения; не придумывать источники, даты, цитаты и реальные события ради драматизма.

Каждому смысловому разделу задать одну функцию, новые сведения/события и примерный объём. План не должен трижды обещать одни и те же критерии, сравнение или финал. Список обещаний хука должен соответствовать тому, что реально раскрыто дальше. Карта истории в UI строится из этого плана и готового текста, а не из трёх общих названий.

### Шаг 3. Сначала narration, потом кадры

Писать цельную озвучку по смысловым разделам, без imagePrompt/animationPrompt и заранее навязанного числа коротких сцен. Для длинного ролика использовать ограниченные блоки по разделам; каждому давать общий план, кратко уже раскрытые мысли, неизменные факты/числа и ближайший переход. Двух последних реплик недостаточно для памяти о всём рассказанном.

Объём считать по сохранённой скорости голоса: ориентир количества знаков = целевые секунды × знаки/с, с общим допуском ±5%. Разделы распределять по содержанию, не поровну. Не заканчивать каждый блок новым вступлением или повторным выводом. Если исходного материала мало для длинного ролика — добавлять полезный пример, объяснение причин, ограничение или контрпример, а не перефразировать прошлый абзац. Если содержательного расширения нет — честно предложить меньшую длительность; не выдумывать факты.

### Шаг 4. Одна содержательная редактура вместо цепочки автопочинок

После полного черновика один редакторский проход должен проверить весь narration и исходное задание. Он **заменяет дублирующие текущие проверки**, а не добавляется поверх всех существующих вызовов. Вывод редактора — короткий список конкретных проблем с цитатой/разделом, объяснением и точечным исправлением; не полный пересказ текста.

Проверять:

1. Семантические повторы: что уже объяснялось, какие абзацы ничего не добавляют. Краткое резюме допустимо только если помогает сделать новый вывод.
2. Причинную связь и последовательность. Не должно быть второго заказа без появления клиента, двух происхождений одного предмета или событий, противоречащих ранее названным дням.
3. Конкретность и пользу. Обещанный пример должен быть примером, а не фразой «умножьте количество на цену». Если предусмотрены расчёты — указаны исходные данные, единицы, расходы и результат; арифметика проверяется локально, не только моделью.
4. Обоснованность утверждений. Интерес, согласие и фактическая оплата — разные сигналы; гипотеза не становится фактом. Для важных реальных утверждений нужны проверяемые исходные материалы либо явное обозначение неопределённости. Вымысел обозначать как вымысел.
5. Естественность речи: постоянная позиция рассказчика, понятные предложения, разнообразный ритм без рубленых одинаковых фраз, отсутствие канцелярита и пустых обещаний.
6. Хук и финал: начало быстро объясняет, почему смотреть; финал отвечает на начальный вопрос, а не обещает раскрыть его позже и не повторяет весь план ещё раз.

Исправлять только проблемные разделы с сохранением согласованного контекста; после правки локально проверить числа, неизменённые факты, объём и отсутствие потерь. Не переписывать хороший префикс ради одной фразы. Не запускать бесконечные платные редакторские циклы: одна автоматическая редактура, затем явный показ оставшихся замечаний/черновика пользователю. Ограничение модели обрабатывает уже реализованный резерв; неизвестный исход платного запроса не повторяется автоматически.

### Шаг 5. Разбивка и визуал не должны портить отредактированный текст

Утверждённую озвучку делить по пунктуации и смыслу на кадры примерно 5–8 секунд, максимум 9. Если предложение длиннее — подобрать естественную границу, не обрывать мысль и не выбрасывать слова. Не назначать всем кадрам ровно 5 секунд. После объединения narration всех кадров должен получаться исходный отредактированный текст, с учётом только согласованного представления пробелов.

Только затем создавать imagePrompt и animationPrompt: один кадр — один конкретный визуальный смысл из соответствующей реплики. Соблюдать сохранённый стиль, героя и язык видимых надписей, если они нужны. После реальной озвучки корректировать кадры по измеренной длительности, не возвращать хороший текст на переписывание из-за маленького расхождения.

### Что означает 8–9/10 и как принимать результат

Пять редакторских критериев по 0–2 балла, всего 10:

| Критерий | Что нужно для высокой оценки |
| --- | --- |
| Выполнение задания и достоверность | Обязательные пункты раскрыты, нет выдуманных фактов/источников и арифметических ошибок |
| Структура и развитие | Каждый раздел добавляет смысл, нет противоречий, лишних повторов и провисаний |
| Конкретность и польза | Понятные примеры, механизмы, детали и ограничения вместо общих слов |
| Разговорный язык | Естественно звучит вслух, единый рассказчик, подходящий аудитории тон |
| Хук и завершение | Начало создаёт честный интерес, финал полностью выполняет обещание |

Цель приёмки — 8–9/10 при чтении пользователем/редактором. Оценка модели — вспомогательная, сама себя качеством не доказывает. Критическая фактическая ошибка, неверная арифметика или потерянное главное обещание не компенсируются красивым языком. Тайминг, сохранность текста и полноценность структуры — отдельные технические критерии, не повод завышать литературную оценку.

Для первичной проверки достаточно трёх коротких примеров: объясняющий ролик с расчётами; история с несколькими персонажами и хронологией; фактический рассказ на предоставленных проверяемых материалах. Сравнить старый и новый результат по одной шкале, лучше без указания версии, и один раз прочитать/прослушать целиком. Только после коротких примеров проверить один длинный сценарий на повторы между разделами. Для готового вставленного сценария отдельно подтвердить дословную сохранность: автоматическая литературная редактура в этом режиме запрещена.
