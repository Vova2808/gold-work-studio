# Отчёт по циклу «аудит → тесты → исправления»

Дата: 2026-07-27.

## 1. Что было сломано и починено

**Приложение не запускалось (блокирующая).** После добавления SOCKS5-прокси пакеты `socks` и `undici`
подключались как внешние CommonJS-модули и ломали ESM-загрузчик Electron: процесс падал сразу после
`start electron app` с `Cannot read properties of undefined (reading 'exports')`.
Починено двумя шагами: SOCKS5 переписан на чистом `node:net` (RFC 1928/1929) + `node:https` — внешних
пакетов больше нет вообще; main-процесс собирается в CommonJS (`dist/main/index.cjs`), штатный формат
для Electron. Проверено прямым запуском собранного приложения: процесс живёт, `app` и `protocol`
резолвятся.

**«Построить пресет» выдавал не тот сценарий.** Обработчик просил модель пересказать переписку чата, а
переписка состоит из служебных реплик («разбор готов, выбери тему») — на выходе получался ролик о том,
как делать ролики. Теперь сценарий пишется из сохранённого разбора темы (ниша, аудитория, транскрипт,
комментарии), длина берётся из настроек проекта, прогресс виден в подсказке. Резервный путь получил
явный запрет писать «ролик про ролики».

**Кадры выходили не в формате проекта.** При включённых референсах генерация уходит на GPT Image, а он
не умеет 16:9 и возвращал 3:2 — кадры выглядели квадратными. Добавлена нормализация: каждый кадр
приводится к формату проекта через FFmpeg (1920×1080 / 1080×1920 / квадрат).

**Видео Google падало на старте** — API требует `store: true` при доставке результата по ссылке.

**Прочее из этого цикла:** дрожание при зуме (теперь зум считается на удвоенном разрешении линейной
формулой), BOM в файле настроек ломал все каналы Lumean, `tsx` не был объявлен зависимостью и тесты не
запускались через `pnpm test`.

## 2. Тесты

Добавлен набор из 15 юнит-тестов (`apps/desktop/src/units.test.ts`) на чистую логику, которая раньше
проверялась только вручную:

- субтитры: разбивка озвучки на реплики, покрытие всей длительности, отсутствие пустых реплик;
- караоке-разметка: сумма таймингов слов равна длине реплики;
- цвета и время ASS, включая некорректный ввод;
- направление камеры: приоритет сцены над проектом, чередование, выключение;
- разбор ответов модели: markdown-фенсы, мусор вокруг JSON, объект-обёртка, понятная ошибка;
- выбор модели озвучки: провайдер + язык, полные id, старые голые имена голосов;
- ссылки YouTube: каналы (`@handle`, `/channel/`, `/c/`, `/user/`) и видео (`youtu.be`, `watch?v=`, `shorts`);
- разбор строки прокси и сообщения об ошибках;
- размеры кадра по формату проекта; целостность каталогов голосов и стилей.

Итого в проекте **30 автотестов** (15 в `packages/core` + 15 в `apps/desktop`), все зелёные.
Для тестируемости чистые функции рендерера и клиента модели вынесены в экспорт — поведение не менялось.

## 3. Замеры

| Проверка | Время | Результат |
| --- | --- | --- |
| Проверка типов (4 пакета) | 6.7 с | без ошибок |
| Автотесты (30 шт.) | 2.3 с | 30/30 |
| Сквозная сборка Final.mp4 (3 сцены, субтитры, музыка, переходы) | 4.5 с | видео собрано |

Оптимизации, влияющие на скорость работы приложения (сделаны в этом и предыдущих циклах): реальная
параллельность очереди (тяжёлые вызовы вне мьютекса), кэш примеров голосов на диске (повторное
прослушивание бесплатно и мгновенно), расход квоты YouTube снижен со ~104 до ~5 единиц на разбор
(uploads-плейлист вместо `search.list`), процент анимации ограничивает число дорогих видео-генераций.
